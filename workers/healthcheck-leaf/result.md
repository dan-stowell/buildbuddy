# Extract health-check types into a leaf package

Healthcheck previously depended on the interfaces catch-all solely for `Checker`
and `CheckerFunc`, pulling unrelated services and external libraries into its
standalone Bazel dependency closure. Move the unchanged definitions and
`CheckerFunc.Check` method to `server/util/healthcheck/checker`, which imports only
Go's `context` package. Keep type aliases in `server/interfaces` so existing callers
and implementations remain compatible, and switch healthcheck to the leaf.
Update the affected BUILD files and add one leaf library target.

The premise was verified before editing: interfaces uniquely contributed 246
first-party labels and 1,299 external labels beyond healthcheck's other nine
library dependencies.

## Dependency reduction

The same Bazel queries were run before and after; their saved output was counted:

```sh
bazel query 'deps(//server/util/healthcheck)' | wc -l
bazel query 'kind("rule", deps(//server/util/healthcheck))'
```

| Metric | Before | After | Reduction |
| --- | ---: | ---: | ---: |
| Total dependency labels | 4,602 | 3,061 | 1,541 |
| First-party dependency labels | 302 | 60 | 242 |
| External dependency labels | 4,300 | 3,001 | 1,299 |
| Total dependency rules | 1,403 | 1,044 | 359 |
| First-party dependency rules | 198 | 49 | 149 |
| External dependency rules | 1,205 | 995 | 210 |

First-party and external counts use the `//` and `@` label prefixes. Labels include
source files; rule counts exclude them. Go and BUILD LOC across interfaces,
healthcheck, and the new leaf increased from 2,587 to 2,603 (+16). The measured
first-party rule reduction is close to the survey's estimate; the external-label
reduction is larger. Binary size was not measured.
