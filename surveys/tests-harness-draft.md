# Integration harness setup survey

Survey of commit `770b88bc89c0b20059d42a237e8c7923ff5b7215`, on 2026-10-13. Research only: no PR, commit or push. Temporary phase timers and readiness-poll experiments were restored after measurement.

## Measurement conventions

All durations below are **local**, on this 2-CPU, 7.7-GiB VM, without remote execution or remote action cache. The root build uses Bazel 9.3.0rc2; `testbazel` uses 9.2.0. CI configuration uses 16-CPU runners and remote infrastructure; the GitHub runs API returned HTTP 403, so **there are no measured CI durations in this report**. Estimates are not CI observations.

“Total test time” means the sum of test/shard durations, not CPU time. Wall-time saving depends on the critical shard and available parallelism. For an unsharded sequential package, the two savings are similar; for sharded packages, do not add every shard's saving to wall time. Candidate estimates overlap: fewer launches/migrations also reduce opportunities for faster readiness polling. Do not sum the table into a promised CI speedup.

Evidence: [source commands and outputs](survey-evidence/source-evidence.txt), [additional commands and outputs](survey-evidence/additional-source-evidence.txt), [test/shard inventory](survey-evidence/inventory.txt). E01–E32 identify commands in these files. Inventory counts are lexical top-level test counts, not a count of assertions or dynamically generated subtests. E25 has 22 matches, one in a documentation comment: **21 actual MakeTempRepo call sites**.

## Package reuse and nested Bazel boundaries

Rules_go shards top-level tests by **index modulo shard count** (E23). Remote-cache's 8 tests / 8 shards and bazel_rbe's 15 / 15 have one test per process; package-level setup sharing would not help without changing sharding. Workflow is 9 / 6, remote-bazel 11 / 7, remote-execution 55 / 11, CI runner 41 / 31. Preserve these shards initially. Build-logs (2 / 1) and stream-run-logs (5 / 1, including the existing warn-mode subcase) offer simpler reuse.

Use a parent test with sequential named subtests to own an app for its entire lifetime, leaving each scenario and all assertions intact. Each child keeps its own connection cleanup and invocation UUID, and separate API keys where those are already used. Build-logs must retain its existing anonymous/default-auth BEP path. Do not use a process-global fixture initialized by an arbitrary child test: its cleanup would run too early. Do not parallelize stream-run-logs while it mutates `UploadBufferSize`.

Nested Bazel's output base is workspace-specific. Retaining a daemon **within the same workspace** can preserve loading/analysis state; sharing one output base across different workspace roots is unsafe. `testbazel` already shares prewarmed downloads/install data. It explicitly disables `repo_contents_cache` to avoid lock contention; do not undo that. A global disk cache could satisfy actions locally and bypass remote cache permission/miss/hit assertions, or RBE executor/task-count assertions, so it is rejected. A shared workspace with unique targets is a separate possibility only for multi-case shards whose scenarios permit it; no blanket task is proposed.

The multi-version prober bypasses testbazel: Bazel 6.5.0 and 7.7.1 raw binaries run with fresh HOME. Existing `--bazel_startup_options` accepts an installation base, and extraction targets already exist. Prewarm these versions while keeping both versions, targets, inputs, shell-argument parsing and actual remote execution. Leave the pre-existing Bazel 8 skip unchanged; this survey proposes no new skip. E31 and prober source/BUILD.

## Readiness and sleep audit

Workflow and remote-bazel poll at 0, .05, .15, .35, .75, 1.55, 3.15, 6.35, 12.75, 25.55 and 51.15 seconds (excluding RPC duration), then sleep to **102.35 s** and fail without a final probe. The loop compares the next delay with one minute, not elapsed time. At a 30-s condition-ready time, detection is 51.15 s; a 100-ms cap detects at ~30.05 s: **21.10 s modelled saving**, not an observed suite speedup. A condition ready at 52 s is missed altogether. [Model command/output](survey-evidence/poll-model.txt). Replace with capped condition polling, a real elapsed deadline of at least the current ~102-s budget (e.g. 120 s), and a final check; preserve all status/error/content predicates.

Redis's 5-ms and ClickHouse/executor registration's 100-ms polls are already short. Build-logs' in-progress assertions use condition polling with a final exact equality check, not a gratuitous fixed sleep. ClickHouse schema's two waits cross a **real second-resolution metadata tick**; preserve them. RBE action-merging/TTL sleeps exercise the expiration behavior; replacing them requires a controllable clock while still covering real expiration elsewhere. `testnetworking.Stop` sleeps one second, but its sole packet-capture consumer has `enablePcap=false`: zero normal-run saving (E16/E30).

## Rejected and low-return ideas

- **Delete/skip/manual-tag slow suites, loosen assertions, remove executor/version/scenario coverage:** rejected. No proven duplicate test was found; the proven duplicate is only one SHA subprocess, not a test.
- **Package-shared app in one-test-per-shard remote-cache/bazel_rbe:** zero launch reduction with current sharding (E02/E23). Combining shards could worsen parallel wall time; do not claim total-time savings as wall-time savings.
- **Global Bazel disk cache or shared output base across workspaces:** can hide remote permission/cache-miss/executor assertions, collide on workspace state or serialize work. Keep shared download/vendor caches already provided.
- **Enable repo_contents_cache / reimplement testbazel prewarming:** already optimized; repo_contents_cache is deliberately disabled to avoid hangs (E07). Existing once-per-process setup matters more than adding another cache layer.
- **Apply --batch everywhere:** controlled results below govern any narrow recommendation; it discards in-memory analysis and would invalidate CLI daemon-reuse coverage. Early mixed cold/load samples are not usable evidence for a batch win.
- **Pool Redis globally:** 5-ms readiness and no persistence already; Redis keys, sharded-ring topology, TTL, PubSub and auth scheduling state are difficult to isolate completely. Cost must justify a separate namespace audit first.
- **New MySQL/Postgres container reuse:** already done in listed DB targets. Image pull/init numbers explain cold local cost but do not imply every CI test pays it. No migration disabling.
- **Fake ClickHouse schema tests or shorten metadata-tick waits:** loses actual schema drift and second-resolution modified-time coverage (E15). Keep real server and per-database migrations.
- **Remove RBE TTL/action-merging sleeps or reduce Bazel retries again:** these exercise expiry/retry paths; not a coverage-preserving edit without another real-path test. `randSleepMillis` currently sleeps a nanosecond duration, so it offers no meaningful speed win.
- **Packet-capture Stop's fixed 1 s:** consumer disables pcap; 0 s ordinary-run saving (E16/E30). Webdriver end-of-test sleep defaults to zero and is only a failure-debug option.
- **Webhook's sleep before first poll:** at most 0.025 s in one test; low return relative to listed work. Cache-proxy sleep is in a benchmark latency interceptor, intentionally modelling latency, not ordinary test setup.
- **Use noisy exploratory measurements as before/after:** rejected. Early nested samples ran during compilation and warming; exploratory shutdown failed due to malformed arguments. Initial DB socket probes could see init servers; MySQL reset auth failures are excluded. Retained raw logs make these limitations inspectable.

## Scope limits

Selected successful/failed local runs are listed with exit codes above; a filtered run is not claimed as full-suite validation. Docker works on this VM and the DB dependency components were measured. Docker RBE requires root for overlay mounts; the survey ran as uid 1000 and did not time it. `/dev/kvm` exists but this user is not in the kvm group; Firecracker/KVM/cloud-credential paths were not benchmarked; this is not a claim that they are unavailable on this VM. Binary testexecutor and full remote-bazel/stream-run-logs suites were not separately timed; their projections use the measured shared primitives and explicitly need verification. No unsupported exe.dev endpoint was used.
