# Measure cache proxy app-link optimization opportunities

The proxy currently exports request and client-facing payload metrics, but those cannot attribute all app-link calls and bytes to a local hit or miss. Add observe-only remote accounting and targeted observations before changing IO behavior. Cache lookups, routing decisions, retries, compression negotiation, returned results, and local write behavior remain as they were.

Existing metrics are retained and reused for client request denominators, chunk traffic/failures, AC unchanged-result counts, enabled FindMissing cache effectiveness, capabilities traffic, and hit-tracker batching. In particular, AC `remote_digest_match` already counts unchanged validation responses, but its byte counter measures the full substituted local result. CAS counters measure blobs and client requests, rather than every outgoing RPC. ByteStream byte counters include local traffic; chunk metrics do not pair SplitBlob NotFound with subsequent successful local service. Existing gRPC message-size histograms provide app-link byte totals by method, but lack the local lookup outcome and REv2 blob compressor. There were no partial-read commit or changed-AC-age metrics, and no FindMissing reuse measurement while caching is disabled. OCIFetcher instrumentation elsewhere records method/role/status and latency, while this proxy had no local-hit attribution.

An observation collector scoped to the request, each BatchReadBlobs batch, or each chunk lookup receives gRPC client stats from the app connection and publishes after the proxy determines the local outcome. This attributes early calls (SplitBlob, OCI metadata) to the eventual hit/miss, and counts internal chunk RPCs individually. It also accounts for events from asynchronous calls that finish after the handler. Cached GetTree creates a separate observation scope for each BatchReadBlobs call, preserving mixed partial-hit and miss RPC/byte attribution across batches. Encryption-bypass batches set their uncacheable outcome before making the remote call, including remote errors. Chunk lookups also use independent scopes: a failed or speculative remote chunk read stays a miss even if the proxy later serves the complete blob locally, and local chunk hit-tracker RPCs retain hit attribution. Method labels use an allowlist. No new metric labels contain digests, image names, groups, invocations, instances, or remote addresses. Existing metrics with group/action labels remain unchanged.

`cache_status` is `hit`, `miss`, `partial`, `uncacheable`, or `not_checked`. These describe the request's local lookup, rather than the remote response: an AC local hit whose result changed remotely is still a local hit. Pass-through operations, writes with no lookup, FindMissing with caching disabled, and background batches use `not_checked`. Directions are relative to the proxy: `sent` to the app and `received` from the app. Remote bytes count gRPC-compressed protobuf message payloads, excluding gRPC/HTTP2 framing, metadata and TLS. Blob bytes separately count REv2/ByteStream/OCI data bytes in their identity/zstd encoding, excluding protobuf envelopes. A successful all-local read normally contributes zero remote reads, but can still contribute a metadata/manifest RPC.

Three flags add optional request-path work, and default off:

- `cache_proxy.observe_find_missing_reuse`: retain at most 100,000 SHA-256 hashed keys in a mutex-protected LRU per CAS proxy. Keys isolate authenticated group, instance, digest function, digest hash/size, and chunk mode. All entries in a request are checked before any are inserted, so duplicates within that request do not count as earlier requests. Windows are inclusive at 1, 5, and 15 minutes; each request refreshes last-seen time. Eviction and restarts underestimate repetition. Counts include requested digests regardless of whether the app reports them present, so reuse is an opportunity estimate, not an exact cache hit prediction. This works with FindMissing caching disabled and skips local-only/blackhole requests and authentication errors.
- `cache_proxy.observe_action_cache_age`: perform an additional metadata lookup only if metadata was not already fetched for the existing TTL path. Ignore observation errors. Changed-result age uses pointer mtime (time since cached/refreshed), not atime. Already-available metadata is observed without enabling the flag; unknown or future timestamps are omitted. Unchanged responses and errors do not enter the age histogram.
- `cache_proxy.identity_zstd_sample_every`: compress approximately one in N eligible identity blobs with zstd; 0 disables sampling. Complete blobs are capped at 1 MiB, with at most two concurrent samples across batch and stream RPCs and nonblocking sample admission. Streaming buffers are bounded to 1 MiB each; oversized blobs, partial/resumed ByteStream transfers, unsuccessful streams, empty data and compressed input are skipped. Known ByteStream sizes must match the observed data. Samples measure compressed/identity bytes: a ratio of 0.5 suggests roughly half the blob payload bytes. Samples are unweighted and favor eligible small blobs; compare with byte totals before estimating savings. The sampler uses its own encoder so it does not increment production compression counters.

Partial-read misses count offset != 0 or limit != 0 requests that actually attempt a remote read after a local blob or chunk miss. A shared atomic observation records each request once, including failed or speculative chunk fetches and a later successful full-blob local fallback. Encryption-bypass reads perform no local lookup and are excluded. Local-only requests (proxy_skip_remote=true) are excluded, even when the local read fails; they also do not attempt or count local write-backs. Commit observations count only attempted local writes, including complete-chunk write-backs on offset reads and failures from incomplete streams and local validation; they do not imply the remote read failed. Writes are counted per attempt (per chunk for chunked reads), while fallback misses are counted per request. Incomplete offset chunks, already-local chunks, and encryption-bypass chunks are not written and add no write outcome. A wasted SplitBlob observation requires NotFound, an eventual local hit, and a successful proxy request. AC revalidation outcomes distinguish the remote's unchanged-digest response, a full changed result, and an error.

# Integration with behavior tasks

No sibling agents or branches named `proxy-splitblob` or `proxy-partial-read` were available in this workspace. The ByteStream hooks record the final read outcome, per-chunk lookup outcomes, the first actual remote fallback after a local miss, and whether attempted read-through or chunk write-backs committed. SplitBlob detection lives in the stats handler, so moving the local lookup ahead of SplitBlob requires no added hook. The partial-read behavior task should retain the final read-outcome counter and emit commit observations only when it actually attempts a local write; skipped writes should not count as failures. AC TTL behavior already present in the checkout is preserved.

The stats handler covers the default app connection, opt-in routing connections, and the hit-tracker connection. Routing registration accepts optional dial options so the proxy can install the observer without changing other routing users. Background atime updates use the observed CAS client, so their RPCs and bytes are also included, normally with `not_checked`. The existing atime request counter isolates those background calls from foreground FindMissingBlobs traffic.

# RPC path attribution audit

Audited every public RPC in ByteStream, CAS, ActionCache, Capabilities and OCIFetcher, plus their internal app calls, the server observation interceptors, default/routed app connections, asynchronous atime calls, synchronous/batched hit tracking, and the blob sampler. The table describes the final implementation. No cache lookup, response, retry, skip-remote policy, encryption policy, or write-back decision changed.

Notation: **R(label; methods)** means `buildbuddy_proxy_remote_rpcs{cache_status=label,method=...}` increments once per attempted outgoing RPC and `buildbuddy_proxy_remote_bytes{cache_status=label,method=...,direction=sent|received}` adds actual compressed protobuf message lengths. ByteStream method labels start with `google.bytestream.ByteStream/`; CAS/AC/Capabilities use their full REv2 service names; OCI uses `oci_fetcher.OCIFetcher/`; tracking uses `hit_tracker.HitTrackerService/Track`. Requests rejected before any app call, or routing/client failures before a gRPC attempt, add neither R nor remote bytes. Remote failures retain the local outcome; received bytes count only messages actually received. Retry attempts count separately.

**D(method)** means `buildbuddy_proxy_link_blob_bytes{method=...,direction=sent|received,compression=identity|zstd|unknown}` adds only encoded blob data observed on that app RPC. Read/Write resource names and batch response/request compressors determine the label. OCI uses identity transport encoding (registry gzip is part of the blob). Eligible complete identity payloads additionally feed `identity_zstd_ratio{method,direction}` only with sampling enabled, within the 1 MiB/two-slot bounds. Partial/resumed/failed/incomplete streams do not produce samples; full chunks on an offset read can qualify independently. Metadata, hit tracking, capabilities and mappings contain no blob data and do not add D.

Existing counter names below omit the `buildbuddy_proxy_` prefix and correspond to the inventory above. BS-read means `byte_stream_read_requests/bytes`, with status, cache_status, proxy_request_type, compression and chunked (legacy bytes also have group_id); BS-write is the corresponding write pair, whose legacy cache_status is always miss. CAS means `content_addressable_storage_requests/digests/bytes` with op, cache_status and payload compression. AC-read/write are their corresponding pairs with status, cache_status, proxy_request_type and read result_source. Existing metric semantics and labels are retained unless noted in the fixes below.
