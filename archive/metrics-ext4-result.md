Measure OCI-to-ext4 conversion IO before selecting optimizations. Adds observe-only counters and histograms with fixed labels, preserves conversion/cache/singleflight behavior, and keeps ociconv changes localized to instrumentation calls. Existing filecache metrics are aggregate across all artifacts: FastLinkFile records hit/miss, but ContainsFile does not. Existing workspace write operations include directory-to-image mke2fs calls but lack reads, phase distributions, and OCI isolation. Existing image-fetch latency includes the outer per-image pull mutex wait and registry/authentication work, so it answers total task image-fetch wait but cannot count actual ext4 conversions.

Optional measurement flags (all default off):

- `executor.ext4_conversion_track_keys`: 4096-key LRU of successful conversions plus at most 4096 active flight hashes. Tracks cache-miss reconversion attempts and overlapping flights without retaining credentials. A recently successful key missing from filecache is evidence of eviction/removal, not proof of eviction. Restart, history eviction, and active overflow undercount; simultaneous first conversions are not classified as reconversions.
- `executor.ext4_conversion_sample_process_io`: adds two `/proc/self/io` reads per measured scope (cleanup has two scopes). These physical IO deltas include concurrent executor work and potentially reaped children; do not sum process and child sources. Child rusage is physical IO in 512-byte units, not logical bytes copied; cached reads may be zero. Process-only phases have no IO samples while this flag is disabled. Missing observations are omitted rather than reported as zero.
- `executor.ext4_conversion_sample_image_size`: adds one stat per successful generated image for apparent and allocated sizes.

Lookup counters count operations, not unique pulls; contains includes singleflight cache rechecks. Conversion counts are attempts after that recheck. Deduped waiter counts exclude canceled callers and the executing caller (the shared return value alone also counts the leader). Credential overlap counts each starting conversion which overlaps another flight for the same storage/image key. Each conversion emits exactly one duration sample for each of the five phases. Cleanup sums unpack-directory and temporary-image removal; repeated scopes are aggregated before flushing. Failed operations are included, and unreached phases emit zero duration. Available IO is likewise aggregated into one sample per phase/source/direction; unavailable IO is omitted. The conversion wait stage includes cache recheck, conversion, singleflight wait, and final link; existing pull timing includes authentication and other pull work. Scrape target `instance` identifies the executor, without adding an executor label.
